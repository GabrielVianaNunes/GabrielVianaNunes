# Architecture

## Branches

| Branch | Purpose |
|---|---|
| `main` | What the profile shows. Only updated from `develop` or from a hotfix |
| `develop` | Integration branch. Features merge here first |
| `feature/*`, `hotfix/*` | One change each, deleted automatically after the merge |
| `output` | Files generated by GitHub Actions. Never edited by hand |
| `output-preview` | Optional, used to try the town workflow without touching `output` |

## Files

```
assets/               pixel art SVGs for the profile (banner, wanted poster, icons)
                      stack-row.svg is generated by scripts/build_stack.py
data/quotes.json      the quote list
data/contributions-fixture.json   real weekly totals, used by tests and previews
scripts/              generators, see below
tests/                unit tests, run on every pull request
docs/town/            design sheets and the release procedure for the western town
docs/wiki/            source of the wiki pages
.github/workflows/    automation, see below
```

## Scripts

| Script | Job |
|---|---|
| `build_assets.py` | Banner, wanted poster, footer, divider and heading icons |
| `build_stack.py` | The stack row as one image |
| `update_quote.py` | The quote of the week |
| `fetch_contributions.py` | Weekly contribution totals through the GraphQL API |
| `town_layout.py` | Weeks to lots, tiers and building kinds. Pure functions |
| `town_palette.py` | Day and night colors, as CSS variables |
| `town_sprites.py` | The 19 pixel art sprites |
| `build_town.py` | Draws the town as two SVGs, with animations |
| `town_design_sheet.py`, `town_contact_sheet.py` | Preview sheets for the docs |

## The western town pipeline

```
GraphQL calendar -> fetch_contributions -> town_layout -> build_town -> output branch -> README
```

1. `fetch_contributions.py` asks only for dates and counts, validates them and writes a small JSON file.
2. `town_layout.py` turns the weeks into lots: tier from the quartiles of the non empty weeks, a building kind from a fixed rotation, and the unique buildings (one sheriff, one bank, up to two churches).
3. `build_town.py` places sprites with `<use>`, adds the scenery and the animations, and writes `western-town-day.svg` and `western-town-night.svg`.
4. The workflow publishes both files to `output`, and the README picks one with a `<picture>` element that follows the viewer's theme.

Every step must succeed before anything is published, so a failure keeps the previous good files.

## Workflows

| Workflow | When | What |
|---|---|---|
| Tests | Pull requests and pushes | `python -m unittest discover -s tests`, read only |
| Western town | Daily 18:30 UTC, manual | Fetch, build and publish the town |
| Weekly quote | Mondays 12:00 UTC, manual | Quote card to `output` |
| Profile 3D contributions | Daily 18:00 UTC | Old graph, to be removed after the town runs for a week |
| Delete merged branch | Merged pull request | Deletes `feature/`, `hotfix/` and `bugfix/` branches |

All third party actions are pinned to full commit SHAs and updated by Dependabot.

## Known gotchas

- GitHub caches images by file name. If a changed image does not update, rename the file.
- Merging a feature into `develop` does not change the profile. The profile only changes after `develop` is merged into `main`.
- Workflows run from the default branch, so a new workflow can only be tried after the release of the code.
