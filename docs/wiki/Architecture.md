# Architecture

## Branches

| Branch | Purpose |
|---|---|
| `main` | What the profile shows. Only updated from `develop` or from a hotfix |
| `develop` | Integration branch. Features merge here first |
| `feature/*`, `hotfix/*` | One change each, deleted automatically after the merge |
| `output` | Files generated by GitHub Actions. Never edited by hand and never merged |

## Files

```
assets/               pixel art SVGs for the profile (banner, wanted poster, icons)
                      stack-row.svg is generated by scripts/build_stack.py
data/quotes.json      the quote list
data/seasons.json     the seasonal decoration windows
scripts/              generators and the season calendar
tests/                unit tests, run on every pull request
docs/seasons/         the plan for the seasonal decorations
docs/wiki/            source of the wiki pages
.github/workflows/    automation, see below
```

## Scripts

| Script | Job |
|---|---|
| `build_assets.py` | Banner, wanted poster, footer, divider and heading icons |
| `build_stack.py` | The stack row as one image |
| `update_quote.py` | The quote of the week |
| `seasons.py` | Which seasonal decoration is active on a date, with moving dates computed |
| `build_seasonal.py` | Builds the four seasonal files for a date or a forced season |
| `season_art/` | One module per season with its decoration. Seasons are found automatically, and each one has a status, `draft` until the owner approves the design and `approved` after, so nothing goes live by accident |
| `build_season_preview.py` | Builds a season for review, with the default look next to it |

## Workflows

| Workflow | When | What |
|---|---|---|
| Tests | Pull requests and pushes | `python -m unittest discover -s tests`, read only |
| Seasonal assets | Daily 03:05 UTC (00:05 in Sao Paulo), manual | Banner, footer, poster and the divider above the graph to `output`, decorated on special dates |
| Weekly quote | Mondays 12:00 UTC, manual | Quote card to `output` |
| Profile 3D contributions | Daily 18:00 UTC | The 3D contribution graph to `output` |
| Delete merged branch | Merged pull request | Deletes `feature/`, `hotfix/` and `bugfix/` branches |

All third party actions are pinned to full commit SHAs and updated by Dependabot. Workflows publish only to `output`, so `main` never receives bot commits.

## Seasonal decorations

```
data/seasons.json -> seasons.py -> season_art -> build_seasonal -> output branch -> README
```

See [Seasonal decorations](Seasonal-decorations) for the calendar, the time zone rule and the approval process.

## Known gotchas

- GitHub caches images by file name. If a changed image does not update, rename the file.
- Merging a feature into `develop` does not change the profile. The profile only changes after `develop` is merged into `main`.
- Workflows run from the default branch, so a new workflow can only be tried after the code reaches `main`.
